# Фронтенд: рабочее место конструктора

SvelteKit 2 + Svelte 5 (руны) + TypeScript, на ките компонентов
[`@monos/ui`](https://github.com/aa-blinov/monos-ui). Приложение показывает
параметрические лекала: пользователь выбирает модель, задаёт мерки и
параметры фасона, видит перестроенный чертёж, проверяет размерную сетку и
выгружает результат в печать.

## Установка и запуск

```bash
npm install
npm run dev        # http://127.0.0.1:5173, /api проксируется на :8000
npm run build      # сборка (adapter-node) в папку build/
npm run start      # запуск собранного сервера, по умолчанию :5173
npm run preview    # предпросмотр собранной версии средствами Vite
npm run check      # svelte-check, ожидается 0 ошибок
npm run check:i18n # словари локализации против бэкенда
```

## Кита компонентов

Кит ставится из репозитория, пока пакет не опубликован в npm:

```bash
npm install github:aa-blinov/monos-ui --legacy-peer-deps
npm install -D tailwindcss@^3.4 postcss autoprefixer
```

Кита собрана на Svelte 4, приложение - на Svelte 5, поэтому её компоненты
компилируются в legacy-режиме и работают как есть. Tailwind видит и классы
киты: в `tailwind.config.js` в `content` включён `node_modules/@monos/ui`,
иначе они вырезаются из сборки.

Приложение не рисует ничего само: цвета, радиусы, шрифт и фокусное кольцо
берутся из токенов `@monos/ui`. Палитра переключается атрибутами
`data-theme` и `data-mode` на корневом элементе.

## Локализация

Словари: `src/lib/i18n/ru.ts` и `src/lib/i18n/en.ts`. Ключи плоские,
сгруппированы по экранам. Текущий язык - стор, компоненты читают перевод
как `$t('ключ')` и перерисовываются сами при его смене. Переключатель в
шапке, выбор сохраняется в localStorage.

Замечания валидатора приходят с бэкенда кодами (`{code, params, text}`), и
фронтенд строит по коду перевод. Проверка `npm run check:i18n` сверяет
набор ключей двух словарей, наличие перевода каждого кода замечания,
совпадение плейсхолдеров с шаблоном из `backend/app/core/issues.py` и
отсутствие переводов несуществующих кодов.

## Зависимость от API

Фронтенд работает **поверх** бэкенда `pattern-engine`; контракт запросов и
ответов зафиксирован в `docs/API-CONTRACT.md`. Используются endpoints:

| Endpoint | Назначение |
|---|---|
| `GET /api/catalog` | список моделей, мерки и описания параметров |
| `POST /api/generate` | построение деталей (полигоны в мм) |
| `POST /api/validate` | ошибки и предупреждения по текущим меркам |
| `GET /api/validate/sizes?model=<id>` | размерная сетка |
| `GET /api/export/{model}.{svg,dxf,pdf}` | выгрузка лекал 1:1 мм |

Бэкенд поднимается из корня репозитория:

```bash
python -m uvicorn app.main:app --app-dir backend --port 8000
```

Адрес бэкенда настраивается переменной `PUBLIC_API_BASE`:

- **не задана** - браузер ходит на относительный `/api` (его проксируют dev- и
  preview-сервер Vite, а также production-сервер `server.js`), а SSR обращается
  к `http://127.0.0.1:8000/api` напрямую;
- **задана** (например `PUBLIC_API_BASE=http://127.0.0.1:8000/api`) - запросы
  идут по этому адресу во всех режимах, включая SSR.

Если бэкенд недоступен, приложение не падает: `src/lib/data.ts` переключается
на фикстуры из `src/lib/fixtures/` и помечает интерфейс плашкой
«офлайн-данные». Фикстуры снимаются с живого бэкенда скриптом
`npm run fixtures` (нужен запущенный backend на :8000), поэтому офлайн-режим
показывает настоящую геометрию, а не приближение.

## Структура

| Путь | Что это |
|---|---|
| `src/routes/+layout.svelte` | Оболочка: язык, палитра, метка готовности |
| `src/routes/+page.svelte` | Каталог моделей |
| `src/routes/pattern/[model]/+page.svelte` | Рабочая область: мерки, параметры, чертёж, экспорт |
| `src/lib/api.ts` | Типизированный клиент API |
| `src/lib/data.ts` | Доступ к данным с откатом на фикстуры |
| `src/lib/types.ts` | Типы, повторяющие `docs/API-CONTRACT.md` |
| `src/lib/i18n/` | Словари локализации и стор текущего языка |
| `src/lib/geometry.ts` | Работа с координатами: пути, габариты, раскладка деталей |
| `src/lib/stores.svelte.ts` | Состояние рабочей области (руны, экземпляр на страницу) |
| `src/lib/components/` | Панели и холст |
| `src/lib/fixtures/` | Офлайн-данные для разработки |
| `src/monos-ui.d.ts` | Типы компонентов кита: пакет поставляет исходники без них |
| `server.js` | Production-сервер: раздаёт сборку и проксирует `/api` на бэкенд |

## Граница ответственности

Фронтенд **не считает геометрию лекал**. Он получает готовые полигоны в
миллиметрах из `POST /api/generate` и рисует их. Припуск на шов, линия шва,
долевая и надсечки приходят из того же ответа; экспорт в SVG/DXF/PDF делает
бэкенд: печать 1:1 требует точной серверной арифметики.

Форма управления мерками и параметрами строится из данных каталога: список
мерок - поле `items[].measurements`, а тип элемента управления параметром
(`<select>` или `<input type="number">` с границами) берётся из описаний
`items[].params`. Списки моделей и параметров в коде не зашиты.

3D-превью - геометрическая драпировка деталей на манекене, **не** примерка
и не промышленная симуляция ткани. Это подписано в интерфейсе.
