# Паспорта основ

Каждая основа лекала живёт в своей папке `backend/app/blocks/<id>/`:

| Файл | Что в нём |
| --- | --- |
| `passport.toml` | название, группа, описание, функция построения, детали, пол и мерки (из них же собирается размерная сетка ГОСТ), параметры фасона, пары сшиваемых срезов, методика-источник |
| `reference.toml` | типовые фигуры и какие проверки «типовая ли основа» к ней применяются, с прибавками по методике и принятыми отклонениями |

Общие файлы рядом:

| Файл | Что в нём |
| --- | --- |
| `options.toml` | общие списки вариантов (посадка, горловина, пол, карман); паспорт ссылается на них по имени |
| `checks.toml` | библиотека проверок: что измерить на деталях, что должно получиться по методике, источник формулы |
| `__init__.py` | чтение и проверка паспортов (pydantic); ошибка в паспорте - ошибка запуска с именем файла и причиной |
| `check.py` | проверка основы: сборка по сетке, пары швов, типовые размеры |

Формулы построения остаются на Python (`draft = "app.drafts.tee:build_tee"`):
их проверяют тесты и ревью, а ошибка в одной основе не ломает остальные.
Каталог для интерфейса (`/api/catalog`) собирается из паспортов, отчёт о
проверке - `/api/blocks` и страница «Справочник → Паспорта основ».

## Паспорт

```toml
id = "skirt"                 # совпадает с именем папки
order = 8                    # место в каталоге
name = "Юбка"
category = "bottoms"
category_label = "Поясные"
description = "Прямая юбка с двумя вытачками на полотнище и молнией в боку."
draft = "app.drafts.skirt:build_skirt"
pieces = ["front", "back", "waistband"]
genders = ["female"]         # для каких фигур строится сетка, первый - по умолчанию
measurements = ["waist", "hip", "height", "waist_to_hip", "skirt_length"]

[source]
kind = "emko"                # emko - по методике; project - упрощение проекта
method = "ЕМКО СЭВ, т. II: основа поясных изделий (юбка)"
notes = "Две вытачки на полотнище, молния в левом боку."

[params.ease_hip]
type = "number"
default = 3
min = 0
max = 30
step = 0.5
unit = "cm"

[params.fit]
type = "select"
options = "fit"              # список из options.toml или свой массив
default = "regular"

[[seams]]                    # пара сшиваемых срезов: деталь.подпись
a = ["front.бок"]
b = ["back.бок"]
ease = [0, 0]                # задуманная посадка стороны a, мм; сверху допуск 5 мм
```

`default = "measurement"` у параметра значит: значение берётся из ходового
размера сетки (длина рукава совпадает с меркой).

## Типовые размеры

```toml
[[figure]]
designation = "164-88-94"    # типовая фигура из сетки ГОСТ
gender = "female"

[checks]
neck_width_back = { ease = [0.5, 1.0] }           # прибавка по методике
armhole_depth = { ease = [1.5, 2.5], accepted = "Почему отличается и почему так задумано" }
back_length = {}
shoulder_ease = {}
```

Проверка из `checks.toml` проходит, если измеренное значение лежит между
`expect` при меньшей и большей прибавке (с допуском 0,3 см). Поле
`accepted` превращает расхождение в принятое отклонение: в отчёте оно
видно с причиной, тест не падает. Пустая причина не принимается.

Язык измерений: `edge(деталь, срез)` - длина среза, `xmax/xmin/ymax/ymin
(деталь, срез)` - крайние координаты среза, `width_at(деталь, y)` - ширина
детали на высоте, `notch(деталь, подпись)` - высота надсечки, `girth(...)` -
доля обхвата, `cut(деталь)`; мерки ЕМКО `Sg, St, Sb, Ssh` (полуобхваты),
`Dts, Vprz, Di, Op`, `rise` - подъём плечевой точки горловины над седьмым
шейным позвонком; `m.*` и `p.*` - мерки и параметры основы. Всё в
сантиметрах.

Бельё ЕМКО СЭВ не описывает: у трусов, боксеров и бралетта нет типовых
размеров, проверяются сборка и пары швов (`kind = "project"`).

## Добавить основу

```bash
python scripts/blocks.py new kimono --name "Кимоно" --from tee
```

Команда копирует паспорт и типовые размеры образца: новая основа сразу
строится и проходит проверку. Дальше:

1. Написать функцию построения в `backend/app/drafts/` и указать её в
   `draft`; поправить `pieces`, `measurements`, `params`, `[[seams]]`,
   `[source]`.
2. Описать типовые размеры в `reference.toml`; новая проверка - в
   `checks.toml` с источником формулы.
3. Проверить: `python scripts/blocks.py check kimono`, затем весь набор
   `python -m pytest backend/tests/test_blocks.py`.
4. Интерфейсу нужны подписи `model.kimono.*` и `piece.*` в
   `frontend/src/lib/i18n` (их сверяет `npm run check:i18n`), эскиз в
   `GarmentSketch.svelte`, 3D-сборка - в `frontend/src/lib/cloth/assembly.ts`.
5. Обновить фикстуры интерфейса: `scripts/make-fixtures.py` при запущенном
   сервере.

## Команды

```bash
python scripts/blocks.py list
python scripts/blocks.py check            # все основы, вся сетка
python scripts/blocks.py check dress coat --quick
python scripts/blocks.py report           # docs/BLOCKS-REPORT.md
```

`check` возвращает код 1, если хоть одна проверка не прошла; тот же отчёт
гоняет `backend/tests/test_blocks.py` в CI.
