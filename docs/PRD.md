# PRD: Shityo

Версия 1, ноябрь 2026. Документ отвечает на вопрос «зачем продукт и что в нём
должно быть». Как устроен код - в ARCHITECTURE.md, методика размеров и
конструкций - в SIZING.md, позиционирование - в PRODUCT.md.

## 1. Цель

Швея или маленькое ателье получает по меркам клиента точное лекало изделия
и печатает его в натуральную величину - за один вечер, без САПР за сотни
тысяч рублей и без навыка построения чертежа с нуля.

Результат работы - не картинка, а лекало, по которому можно кроить:
швы сходятся, длины сопряжённых срезов совпадают, контрольный квадрат на
печати равен 10 см.

## 2. Для кого

| Сегмент | Кто | Что важно |
| --- | --- | --- |
| Основной | Частная швея, 1-10 индивидуальных заказов в неделю | Быстро получить основу под мерки клиента, подогнать посадку, распечатать на А4 |
| Основной | Микро-ателье, 2-5 мастеров | Хранить клиентов и историю мерок, повторять заказы, не терять проекты |
| Вторичный | Продвинутая любительница | Шить себе по своим меркам вместо покупных выкроек |
| Вне фокуса | Фабрики и технологи | Градация на тираж, раскладка на ленту, многопользовательская работа |

Типичный пользователь работает с ноутбука в мастерской, часто на расстоянии
от экрана и не всегда с идеальным зрением. Поэтому интерфейс должен
читаться крупно, а главное действие на каждом экране - сразу видно.

## 3. Задачи пользователя (Jobs to be done)

1. «Пришла клиентка - хочу за 10 минут получить основу платья по её меркам».
2. «Клиент вернулся через полгода - хочу открыть его прошлый заказ и
   поправить под новые мерки».
3. «Мерок нет - хочу начать с типового размера по ГОСТ и потом уточнить».
4. «Хочу понять, как сядет вещь, до раскроя ткани».
5. «Хочу распечатать лекало дома на А4 и склеить без ошибок».
6. «Шью комплект (брюки и жилет) одному клиенту - хочу держать всё вместе».

## 4. Основные сценарии

### 4.1 Первый проект

Каталог основ -> «Новый проект» -> чьи мерки (клиент, типовой размер по
ГОСТ с ростом, демо) -> посадка (прилегающая, классическая, свободная,
оверсайз) -> редактор -> проверка швов -> печать. Новичку весь путь
показывается по шагам, пока он не распечатает первое лекало.

### 4.2 Подгонка

В редакторе слева мерки и посадка, в центре чертёж или 3D-примерка, справа
проверка. Любая правка пересчитывает лекало сразу. Правки можно отменить,
проект сохраняется сам, к любой прошлой версии можно вернуться.

### 4.3 Повторный заказ

Кабинет -> проект или клиент -> новые мерки -> те же основы с новой
посадкой. История мерок клиента не перезаписывается.

## 5. Требования

Приоритет: P0 - без этого продукт не решает задачу, P1 - нужно для
удобной ежедневной работы, P2 - развитие.

## 6. Метрики успеха

| Метрика | Цель |
| --- | --- |
| Доля новых пользователей, дошедших от каталога до печати в первый визит | 40 % |
| Время от открытия основы до PDF | меньше 10 минут |
| Проекты, открытые повторно (вторая примерка) | 30 % сохранённых |
| Ошибки построения в аудите формул | 0 |
| Обращения «лекало не сошлось по шву» | 0 |

## 7. Ограничения и принципы

- Данные - только в браузере пользователя. Мерки клиентов на сервер не уходят.
- Миллиметры в чертеже, сантиметры в мерках.
- Внешние выкройки открываются у издателя и не превращаются в наши основы.
- Размеры и прибавки - по ГОСТ, ОСТ и ЕМКО СЭВ, с источниками в SIZING.md.
- Каждый новый параметр конструкции проходит аудит формул по всем
  размерам, ростам и посадкам.

## 8. Чего не делаем

Регистрация и облако, оплата, градация на тираж, раскладка на ленту для
фабрик, свободное рисование лекал без основы (кроме редактора деталей с нуля),
промышленная симуляция посадки.

## 9. Дальнейшие шаги

1. Вкладки: несколько лекал и клиент в одном проекте.
2. 3D: фаза сшивания швов, складки юбочной части платья у бёдер, кромка верха стопы.
3. Пошаговое обучение первого проекта.
4. Типовые исправления посадки.
5. Расход ткани.

Обоснование по рынку - в MARKET-ANALYSIS.md: у конкурентов (Грация, Ассоль,
Redcafe, Valentina, Lekala, Bootstrap, CLO) сильнее всего востребованы
исправления посадки, моделирование поверх основы и расход ткани.
