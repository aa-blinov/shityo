# Roadmap

Оценки в человеко-неделях для команды из 2-3 человек. Один человек -
это неделя рабочего времени, три человека при параллельной работе дают
примерно половину срока по интеграционным задачам.

## Что уже есть (пилот, неделя 1)

Рабочий сервис с параметрическими конструкциями четырёх типов изделия:
футболка, рубашка, брюки, юбка.

| Что сделано | Где |
|---|---|
| Геометрическое ядро: точки, кубические Безье, адаптивная аппроксимация, смещение контура | `backend/app/core/geometry.py` |
| Параметрические конструкции с формулами от мерок | `backend/app/drafts/` |
| Каталог моделей и размерные сетки | `backend/app/drafts/catalog.py`, `backend/app/core/sizes.py` |
| Валидация геометрии, припусков, мерок и параметров | `backend/app/core/validation.py` |
| Экспорт SVG / DXF / PDF 1:1 мм | `backend/app/export/` |
| HTTP API | `backend/app/api/routes.py` |
| Браузерное приложение: каталог, 2D-просмотр, размерная сетка, 3D-превью | `frontend/` |
| Юнит, API и Playwright-тесты | `backend/tests/`, `e2e/tests/` |

## Этап 1. MVP (выполнен)

**Функциональный объём.** Четыре типа изделий, ввод мерок и параметров
фасона, перестроение конструкции в реальном времени, 2D-просмотр с
наложением слоёв (линия шва, припуск, зерно, надсечки, вытачки), размерная
сетка, экспорт в SVG/DXF/PDF 1:1.

**Технические задачи.** Геометрическое ядро; конструкции; валидация;
экспорт с разбивкой на листы; API; фронтенд; тесты.

**Критерии готовности (проверены).**
1. `pytest backend/tests` - зелёные.
2. `npx playwright test` в `e2e/` - зелёные, сценарий проходит в браузере.
3. `npm run build` во `frontend/` - собирается, `npm run check` без ошибок.
4. Экспорт открывается: SVG - валидный XML, DXF читается ezdxf, PDF -
   открывается и имеет правильный размер страницы.
5. Один и тот же вход даёт тот же чертёж (детерминизм, тест на повтор).

## Этап 2. Расширение (4-6 недель)

**Функциональный объём.**
- Библиотека моделей: трикотаж (с растяжимостью и другими прибавками),
  платья, каргоны, спортивные брюки, детская одежда.
- Сложные фасоны: реглан, летучий рукав, разрезной подол, капюшон,
  отложной воротник на подкладке, накладные карманы.
- Ручное редактирование в браузере: перенос контрольных точек кривых,
  перетаскивание надсечек, добавление вытачек.
- Импорт лекал из внешних форматов (DXF, SVG) с восстановлением
  параметризации.
- Размерная градация: построение всей размерной сетки по одной модели.
- Раскладка деталей на раскрой: оценка расхода ткани.

**Технические задачи.**
1. Перенос конструкций в декларативный формат `docs/FORMAT.md`:
   конвертер `код -> JSON` + редактор моделей.
2. Песочница вычисления формул: AST вместо `eval`, белый список функций.
3. Градация: правила изменения точек при переходе размера.
4. Раскладка: алгоритм укладки деталей (сначала жадный, затем
   оптимизация).
5. Импорт: разбор DXF (сегменты, дуги, слои) и восстановление точек.

**Зависимости.** Этап 1 (как платформа) + решение по лицензиям из
`docs/research/01-open-pattern-sources.md`.

**Риски.**
- Лицензия исходных лекал: CC-BY-SA на дизайны требует раскрытия
  производных лекал под тем же лицензионным режимом. Проверять до
  встраивания, а не после.
- Перенос кода в JSON - работа с откатом: старый путь должен остаться
  рабочим, пока новый не покрыт теми же тестами.
- Раскладка деталей - отдельная сложная задача, лучше делать её последней.

**Критерии готовности.** Модель в JSON редактируется без программиста;
импорт DXF даёт деталь с корректным контуром; градация строится по
всем размерам сетки; раскладка укладывает детали без пересечений.

## Этап 3. Продвинутая версия (6-10 недель)

**Функциональный объём.**
- 3D-примерка на параметрическом манекене по индивидуальным меркам.
- Симуляция ткани: поведение ткани зависит от её свойств (растяжимость,
  вес, нити), а не от абстрактной ткани.
- Сохранение проектов, версии, командная работа.
- Производственный контур: выход в форматы раскроя (AAMA/ASTM DXF),
  интеграция с 1С и textile-системами.

**Технические задачи.**
1. Параметрический манекен по антропометрии (процедурная модель тела).
2. Сборка деталей по швам в 3D: сопоставление рёбер, посадка по точкам.
3. Физика ткани в браузере (Rapier soft bodies или WebGPU-решатель).
4. Проекты: версионирование, хранение, API.

**Зависимости.** Этап 2 + выбор физического движка. По данным
`docs/research/03-frontend-3d-stack.md` реалистичная ткань в браузере
возможна, но только в Chrome/Edge для WebGPU-пути; кросс-браузерный вариант
на Rapier менее точен.

**Риски.**
- Физика ткани в браузере - самая рискованная часть: точность ниже
  промышленной, поведение зависит от браузера и GPU.
- Сопряжение деталей в 3D - основная сложность: контуры из 2D не несут
  информации о том, какие рёбра сшиваются.

**Критерии готовности.** Изделие собирается на манекене из мерок;
поведение ткани зависит от выбранного материала; детали из разных моделей
сшиваются без ручной подгонки.

## Что проверять в первую очередь (технические гипотезы)

1. **Реальная ли пригодность открытых конструкций.** Файл
   `docs/research/01-open-pattern-sources.md` отвечает на вопрос про
   библиотеку; гипотеза для проверки - «свободных параметрических
   конструкций хватит, чтобы не рисовать каждую самому».
2. **Качество построения против отзывов конструктора.** Собственные
   формулы - это гипотеза о корректности посадки. Нужен хотя бы один
   внешний эксперт, который сошьёт лекало по нашим размерам.
3. **Реалистичность 3D-примера.** Примерка покажет, что параметризация
   работает не только на бумаге.
4. **Нужен ли свой градационный движок.** Проверяется сравнением с
   существующими системами: если закрытые системы умеют то же и стоят
   меньше, чем разработка, - покупаем.
