# Внутренний формат базовых моделей

Формат описывает **параметрическую конструкцию**, а не готовую выкройку:
мерки, диапазоны, формулы и правила. Выкройка получается детерминированно
применением правил к меркам.

Хранится как JSON (один файл на модель) в `models/<id>.json`. Формат
версионируется: поле `format_version` обязательно, движок отказывается
читать неизвестную версию.

> **Текущее состояние репозитория.** Формат выше - целевой interchange
> для импортируемых моделей и для будущего каталога на диске. Пилота
> реализует те же сущности, но конструкции заданы кодом
> (`backend/app/drafts/*.py`), а не JSON: для пилота важнее детерминизм и
> тестируемость, а не редактируемость моделей без программиста.
> Каталог моделей уже отдаётся в JSON (`GET /api/catalog`) и содержит те
> же поля `measurements`, `params`, `default_measurements`, `pieces`, что и
> формат ниже. Перенос кода конструкций в JSON - первая задача этапа
> «Расширение»: конвертер `code -> json` пишется один раз, а дальше
> модель правится конструктором.

## 1. Общая структура

```json
{
  "format_version": "1.0",
  "id": "mens_shirt",
  "name": "Мужская рубашка",
  "category": "tops",
  "genders": ["male"],
  "version": "1.2.0",
  "license": {
    "code": "MIT",
    "design": "CC0-1.0",
    "attribution": "Исходная конструкция: ...",
    "source_url": "https://..."
  },
  "measurements": [
    { "id": "bust", "label": "Обхват груди", "unit": "cm",
      "min": 70, "max": 140, "default": 100, "required": true }
  ],
  "size_standards": ["RU 42-54", "EU 38-54", "ISO"],
  "params": [
    { "id": "fit", "type": "enum", "options": ["slim", "regular", "loose"],
      "default": "regular" },
    { "id": "ease_bust", "type": "number", "default": 8, "min": 0, "max": 25,
      "unit": "cm" }
  ],
  "pieces": [ ... ],
  "grading": { "base_size": "46", "rules": [ ... ] },
  "provenance": { "method": "классическая система пропорциональных мерок",
    "notes": "..." }
}
```

## 2. Описание детали

```json
{
  "id": "front",
  "name": "Перед",
  "cut": 1,
  "mirrored": false,
  "seam_allowance": { "default": 10, "unit": "mm" },
  "points": {
    "A":  { "x": "0",            "y": "0" },
    "B":  { "x": "neck_half",   "y": "0" },
    "C":  { "x": "half_width",  "y": "armhole_depth" }
  },
  "curves": [
    { "id": "c_neck", "type": "cubic",
      "from": "A", "to": "B",
      "control": [ "A", "P1", "P2", "B" ] }
  ],
  "outline": { "type": "path", "segments": [ { "line": ["A", "B"] },
      { "curve": "c_neck" }, { "line": ["B", "C"] } ] },
  "notches": [ { "at": "C", "label": "пройма" } ],
  "grainline": { "from": "A", "to": "D", "angle": 90 },
  "internal_lines": [
    { "type": "dart", "from": "E", "to": "F", "label": "вытачка" }
  ],
  "seams": [
    { "id": "s_side", "piece": "front", "edge": "side",
      "mates_with": "front:s_side_back", "tolerance_mm": 2 }
  ]
}
```

## 3. Формулы

Формула - строка в ограниченном языке выражений, без произвольного кода:

- Числа: `10`, `2.5`.
- Имена мерок и параметров: `bust`, `ease_bust`.
- Имена точек: `A`, `B`.
- Операторы: `+ - * / ^`, скобки.
- Функции: `min`, `max`, `abs`, `sqrt`, `sin`, `cos`, `pi`, `if(cond, a, b)`.
- Условные конструкции: `{ "if": "<условие>", "then": ..., "else": ... }`.

Условие пишется как выражение с операторами сравнения `== != < <= > >=` и
логическими `and`, `or`, `not`.

Выражения вычисляются **песочницей**: свой AST, никакого `eval` над
Python-кодом. Проверяются: только известные имена, только разрешённые
функции, глубина выражения, отсутствие вызовов через атрибуты.

## 4. Правила градации

```json
{ "id": "bust", "apply_to": "points", "targets": ["A", "B"],
  "rule": "delta" }
```

- `delta` - линейное изменение на размер.
- `ratio` - умножение на коэффициент.
- `formula` - собственное выражение.

Градация меняет размерную сетку, а не индивидуальную конструкцию:
индивидуальные мерки - это другой режим с теми же формулами.

## 5. Конвертация внешних источников

| Источник | Что переносится автоматически | Что восстанавливается вручную |
|---|---|---|
| FreeSewing (JSON-дизайны) | Точки, формулы, параметры, названия деталей | Метки надсечек, долевые нити, лицензия дизайна |
| Seamly2D / Valentina (`.val`, `.vit`) | Точки, линии, формулы (перевод в наш DSL) | Порядок построения, технологические метки |
| DXF-контуры | Только геометрия контура | Всё остальное: параметризация отсутствует |
| SVG с метаданными | Контур, если есть слои | Формулы и мерки |

Автоматический импорт всегда оставляет модель в состоянии `static`,
если параметризация не выводится. Статичная выкройка не выдаётся за
параметрическую конструкцию: в каталоге у неё стоит пометка
`parametrization: "static"`, и UI предупреждает пользователя.

## 6. Что модель обязана содержать

1. Список мерок с диапазонами и значениями по умолчанию.
2. Список параметров фасона с типами и допустимыми значениями.
3. Опорные точки с формулами.
4. Кривые (кубические Безье, дуги, прямые).
5. Контуры деталей, собранные из точек и кривых.
6. Связи между деталями: какие швы сопрягаются и с каким допуском.
7. Технологические метки: надсечки, зерно, вытачки, сгибы.
8. Происхождение и лицензию.

Модель без пункта 6 не проходит проверку `validate`: сопряжение деталей
нельзя проверить, а именно оно даёт технологическую пригодность.
